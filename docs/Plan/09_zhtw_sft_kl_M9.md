## 1. 方法（相對 M8 的改動）
- **資料清理**（`m9_factcheck.py`、`m9_build_sft.py`）：
  - 維基 fact-check：137 主題中 122 個取得中文維基全文；530 則知識答案由官方 QAT（思考關 judge、參考 1500 字）判定：正確 454、錯誤 65（以參考資料重生成並再判定正確而修正 51、丟棄 14）、無法判斷 11。
  - 思考 trace 去指引：203 則移除提及 system 指引／persona 的句子。

- **訓練**（`m9_train.py`）：rank 8（可訓 12,079,104）、1 epoch 246 步、lr 4e-5（warmup 15、cosine 至 0.1×）、batch 4；loss = SFT CE ＋ 1.0·KL(teacher‖student)，每步一段 512-token 一般文本（wikitext-2 train＋主題維基，排除 PPL 評測文本）。teacher＝同網路繞過 LoRA（即官方 QAT）。checkpoint 每 25 步、不刪除。
  - 23:08 起單次跑完、0 次崩潰（約 40–45 秒／步、峰值 13.6GB），02:18 完成。val 0.712 →（100）0.565 →（150）0.541 →（200）0.530 →（246）0.527；KL 約 0.006–0.013。

## 3. 發現
1. **兩項目標皆達成**：PPL 與官方幾乎相同（+0.03%／+0.17%，M8 為 +118%），知識 12/15 與官方相同，且 M8 的「玉山→太魯閣山」等自信錯事實消失。KL-to-teacher＋降強度（rank 8、1 epoch、lr 4e-5）＋fact-check 有效。
2. **思考關保留 M8 大部分風格改善**：0 英文、0 簡體、指令 15/15、亂碼 9/10（M8 10/10，官方 8/10）；回答變短、總時間 median 由 2.3–2.9 秒降到 0.74–0.86 秒。
3. **思考開未改善亂碼題**：亂碼 2/5（=官方，M8 為 5/5），g01 思考開仍以英文回覆；但思考變短（思考 tokens −35%），首答案時間 10.0→5.9 秒。推測原因：思考類訓練資料少（gib 類只有非思考版），且 KL 把行為拉回官方。
4. **思考 trace 指引洩漏大幅減少**：思考開輸出中「Traditional Chinese assistant／persona／system prompt」等關鍵字出現次數 M8 66 → M9 6（官方 14）。
5. step 50 仍有英文／簡體，step 100 起穩定；之後 zh PPL 緩升，代表較長訓練開始偏離。

## 4. 結論與建議
- **M9 step 100 建議取代官方 QAT 作為思考關預設**：品質（PPL、知識）不輸官方，zh-TW 風格與延遲明顯較好，大小相同且打包無損。
- 思考開模式 M9 與官方持平（亂碼 2/5、g01 英文），若需改善：補 gib_think／unans_think 資料（含 g01 類亂碼的思考版繁中澄清），或對思考開子集降低 KL 權重，再以同一流程選點。
- 可接續：M7 的 nothink-default 打包套用到 M9、思考上限（think budget）以進一步壓低思考開延遲。
